================================================================================
  УНИСПОРТ (UniSport) — веб-приложение для управления студенческими
  спортивными лигами в университете
================================================================================

1. НАЗНАЧЕНИЕ
--------------------------------------------------------------------------------
Информационная система предназначена для автоматизации учёта и организации
студенческих спортивных соревнований: лиги по видам спорта, команды и составы,
заявки игроков, расписание и результаты матчей, уведомления участников,
администрирование пользователей и отчётность.

Целевые пользователи:
  - Игрок (студент-участник)
  - Тренер (капитан/руководитель команды)
  - Менеджер лиги (организатор соревнований)
  - Администратор системы

Клиентский доступ — через браузер (адаптивный веб-интерфейс на Bootstrap 5).
Дополнительно доступен REST API для получения списков лиг и матчей.


2. ТЕХНОЛОГИИ
--------------------------------------------------------------------------------
  - Python 3.12+
  - Django 4.2.14 (архитектура MVT)
  - Django REST Framework 3.15 — REST API
  - drf-yasg — документация OpenAPI / Swagger UI
  - SQLite — база по умолчанию (разработка)
  - PostgreSQL — production (через переменные окружения)
  - ReportLab — экспорт PDF-отчётов
  - Gunicorn — WSGI-сервер для production
  - HTML-шаблоны Django, CSS (static/css/unisport.css), Bootstrap 5.3

4. УСТАНОВКА И ЗАПУСК
--------------------------------------------------------------------------------
4.1. Требования
  - Python 3.12 или совместимая версия
  - pip, venv (рекомендуется)

4.2. Установка зависимостей (Windows, PowerShell)

  cd путь\к\UniSport
  python -m venv venv
  .\venv\Scripts\Activate.ps1
  pip install -r requirements.txt

4.3. Миграции и суперпользователь

  python manage.py migrate
  python manage.py createsuperuser

  Суперпользователь получает роль ADMIN в интерфейсе приложения и доступ
  к /admin/ (стандартная панель Django).

4.4. Запуск сервера разработки

  python manage.py runserver

  Сайт: http://127.0.0.1:8000/
  Django Admin: http://127.0.0.1:8000/admin/
  Swagger API: http://127.0.0.1:8000/swagger/
  OpenAPI JSON: http://127.0.0.1:8000/openapi.json

4.5. Сбор статики (production)

  python manage.py collectstatic

4.6. PostgreSQL (production)

  Задайте переменные окружения перед запуском:

  set POSTGRES_DB=unisport
  set POSTGRES_USER=unisport
  set POSTGRES_PASSWORD=ваш_пароль
  set POSTGRES_HOST=localhost
  set POSTGRES_PORT=5432

  Либо DATABASE_URL (если настроено в окружении).
  Без POSTGRES_* используется SQLite (файл db.sqlite3).

4.7. Переменные окружения (безопасность)

  DJANGO_SECRET_KEY   — секретный ключ (обязателен в production)
  DJANGO_DEBUG        — True/False (по умолчанию True)
  DJANGO_ALLOWED_HOSTS — список хостов через запятую (по умолчанию *)


5. РОЛИ И ПРАВА ДОСТУПА
--------------------------------------------------------------------------------
Роль хранится в модели UserProfile (поле role). Эффективная роль в интерфейсе
вычисляется функцией _resolve_user_role() в views.py:

  ADMIN    — суперпользователь Django ИЛИ is_staff=True
  MANAGER  — profile.role = MANAGER
  COACH    — profile.role = COACH
  PLAYER   — profile.role = PLAYER (роль по умолчанию при регистрации)

Ограничение доступа к страницам — через RoleRequiredMixin (allowed_roles).

Кратко по возможностям:

  Гость (не авторизован):
    - главная, о проекте, каталоги лиг/команд/игроков/тренеров, расписание
    - регистрация, вход

  Игрок (PLAYER):
    - профиль, панель /roles/player/
    - заявка в команду в рамках лиги (одна активная заявка на лигу)
    - отмена своей заявки
    - голосование за MVP матча (если доступно)
    - уведомления

  Тренер (COACH):
    - панель /roles/coach/
    - управление составом своих команд (/teams/<id>/roster/)
    - принятие/отклонение заявок игроков
    - подтверждение участия команды в матче
    - учёт посещаемости игроков на матче
    - сообщение игрокам команды

  Менеджер (MANAGER):
    - панель /roles/manager/
    - создание и редактирование лиг (где он назначен manager)
    - команды, матчи, объявления, назначение тренеров
    - ввод результатов, статусов матчей, голов

  Администратор (ADMIN):
    - всё, что менеджер, плюс раздел /staff/* и /roles/admin/
    - управление пользователями, ролями, аналитика, аудит, backup/restore
    - импорт команд из CSV
    - Django Admin (/admin/)


6. РЕГИСТРАЦИЯ И ВХОД
--------------------------------------------------------------------------------
Регистрация: /register/

  Поля: логин, имя, фамилия, email, факультет, группа, курс, возраст, пароль.
  Email должен оканчиваться на @rea.ru (валидация в RegistrationForm).
  После регистрации создаётся User + UserProfile с ролью PLAYER, пользователь
  автоматически входит в систему.

Вход: /accounts/login/
Выход: /accounts/logout/
Смена пароля: /accounts/password_change/
Восстановление пароля: /accounts/password_reset/ (письма в консоль при
  EMAIL_BACKEND = console; для реальной почты настройте SMTP в settings.py)


7. ОСНОВНЫЕ СУЩНОСТИ (МОДЕЛИ ДАННЫХ)
--------------------------------------------------------------------------------
UserProfile      — профиль: роль, факультет, группа, курс, возраст, bio, фото
League           — лига: вид спорта, сезон, статус, менеджер, связь M2M с Team
Team             — команда: название, факультет, курс, тренер (captain),
                   игроки (players), запас (reserve_players)
Match            — матч: лига, хозяева/гости, дата, площадка, счёт, статус
TeamJoinRequest  — заявка игрока в команду (уникально: user + league)
CoachAssignment  — назначение тренера менеджером на лигу/команду
MatchParticipation — подтверждение участия команды в матче
PlayerAttendance — посещаемость игрока на матче
GoalEvent        — гол/очко: автор, минута, команда
MatchMVPVote     — голос за MVP (один голос voter на матч)
Announcement     — объявление в лиге
Notification     — уведомление пользователю (текст, ссылка, прочитано)
AuditLog         — журнал HTTP-запросов (middleware)
CoachRosterAction — история изменений состава тренером

Виды спорта (League.Sport): баскетбол, футбол, волейбол, мини-футбол.
Статусы лиги: планирование, активна, завершена.
Статусы матча: запланирован, в процессе, завершён.


8. КАК РАБОТАЕТ ПРИЛОЖЕНИЕ (БИЗНЕС-СЦЕНАРИИ)
--------------------------------------------------------------------------------
8.1. Организация лиги (менеджер / админ)

  1) Создать лигу: /leagues/create/ (вид спорта, сезон, статус).
  2) Создать команды: /teams/create/ и привязать к лиге.
  3) Назначить тренеров: /manage/coaches/
  4) Управлять командами лиги: /manage/leagues/<id>/teams/
  5) Создать матчи: /matches/create/
  6) Публиковать объявления: /announcements/create/
  7) Менять статус лиги: /leagues/<id>/status/

8.2. Участие игрока

  1) Зарегистрироваться на /register/
  2) Открыть лигу /leagues/<id>/, выбрать команду, подать заявку
     (/leagues/<league_id>/apply/<team_id>/)
  3) Дождаться решения тренера (уведомление в /notifications/)
  4) После принятия — игрок в составе команды, видит матчи в расписании

8.3. Работа тренера

  1) Панель /roles/coach/
  2) Заявки: /join-requests/<id>/decide/ (принять / отклонить)
  3) Состав: /teams/<team_id>/roster/ — добавить/удалить игроков
  4) Перед матчем: подтвердить участие /participation/<id>/confirm/
  5) На матче: /matches/<match_id>/teams/<team_id>/attendance/ — отметки
     присутствия (присутствует, отсутствует, травма, учёба)

8.4. Проведение матча (менеджер / админ)

  1) Расписание: /matches/schedule/ или /matches/all/
  2) Карточка матча: /matches/<id>/
  3) Статус: /matches/<id>/status/ (запланирован → в процессе → завершён)
  4) Счёт: /matches/<id>/result/
  5) Голы: /matches/<id>/goal/
  6) MVP: игроки голосуют /matches/<id>/vote-mvp/

  На странице лиги автоматически строится турнирная таблица (очки за победы).

8.5. Уведомления

  Система создаёт записи Notification при ключевых событиях (заявки,
  матчи, результаты — по логике в views.py). Пользователь видит список на
  /notifications/, счётчик непрочитанных — в шапке сайта. Отметка прочитанным:
  /notifications/<id>/read/

8.6. Администрирование

  Панель: /roles/admin/
  Пользователи: /staff/users/ (создание, редактирование, смена роли, удаление)
  Команды: /staff/teams/
  Аналитика и отчёты: /staff/analytics/
    - активность по факультетам
    - статистика матчей по видам спорта
    - экспорт CSV/PDF (?type=faculty|matches&format=csv|pdf)
  Импорт CSV команд: /staff/import-csv/ (поля: name, faculty, league_id)
  Журнал аудита: /staff/logs/
  Резервная копия: GET /staff/backup/ → JSON (dumpdata)
  Восстановление: POST /staff/restore/ → загрузка JSON (loaddata)

  Параллельно доступна стандартная Django Admin: /admin/

10. REST API
--------------------------------------------------------------------------------
Эндпоинты только на чтение (ListAPIView):

  GET /api/leagues/
    Поля: id, sport, sport_display, season, status, manager

  GET /api/matches/
    Поля: id, league, home_team, away_team, date_time, location,
          score_home, score_away, status

Документация: /swagger/ и /openapi.json (drf-yasg, доступ без авторизации
в текущей конфигурации; для production рекомендуется ограничить доступ).

Тестирование API: Postman, curl или Swagger UI.

12. БЕЗОПАСНОСТЬ И НАДЁЖНОСТЬ
--------------------------------------------------------------------------------
  - Пароли хешируются стандартными средствами Django
  - CSRF-защита для POST-форм
  - RoleRequiredMixin — проверка роли перед доступом к действиям
  - AuditLogMiddleware — запись каждого HTTP-запроса (метод, путь, код, IP)
  - Ограничения БД: уникальность заявки на лигу, разные команды в матче
  - Резервное копирование через dumpdata/loaddata (админ-раздел)

Рекомендации для production:
  - DJANGO_DEBUG=False
  - надёжный DJANGO_SECRET_KEY
  - HTTPS, ограничение ALLOWED_HOSTS
  - PostgreSQL и регулярные бэкапы БД
  - ограничить доступ к /swagger/ и /staff/restore/

15. РЕШЕНИЕ ПРОБЛЕМ
--------------------------------------------------------------------------------
  - «No module named django» — активируйте venv, pip install -r requirements.txt
  - Ошибки миграций — python manage.py migrate
  - Нет прав на действие — проверьте роль в профиле или назначьте через
    /staff/users/<id>/role/ (админ)
  - Регистрация не проходит — email должен быть @rea.ru
  - Менеджер не видит лиги — в League.manager должен быть этот пользователь
  - PDF без кириллицы на Linux — установите шрифт DejaVu (путь в views.py)
  - После restore — перезапустите сервер при необходимости
